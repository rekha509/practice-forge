## Decisions Made
(Phase 1 decisions unchanged — sandbox isolation via `sandbox-runner`, CPU-as-wall-clock-at-1-CPU, `IssuedLedger.is_recycled` denormalization, configurable docker.sock mount, host venv on Python 3.11 — see `docs/adr/0001-0003` and prior PROGRESS.md history in git log if needed.)
- `pypdf` used as a placeholder for marker-pdf; title/author/edition extraction is a regex heuristic, not an LLM call — see `docs/adr/0004`. Why: Phase 2's gate is about dedup/persistence correctness, not extraction quality; marker-pdf needs real model weights that aren't worth standing up yet, and avoiding an LLM call here means dedup logic is fully testable at zero API cost.
- MinHash `scheme` pinned explicitly to `"affine32"` (datasketch's own default) in both `build_minhash` and `list_to_minhash` rather than relying on the library's implicit default. Why: datasketch >= 2.0 raises on reconstructing a `MinHash` from stored `hashvalues` without an explicit scheme (discovered when the Phase 2 gate first ran) — pin it so persisted signatures always deserialize the same way regardless of what datasketch's own default happens to be in the future.
- `tests/conftest.py`'s `db_session` fixture truncates `books`/`pages` at **setup**, not just rollback at teardown. Why: discovered mid-Phase-2 that a rollback-only fixture doesn't clean up rows a previous *manual* `pf ingest` CLI run (or a test that crashed before reaching its own rollback) already committed — the next test then sees stray data and fails confusingly. Setup-time truncation makes each test hermetic regardless of what left the DB in whatever state.
- Discipline auto-detection (spec: "auto-detected at ingest from title, TOC and sampled content; confirmable/overridable by the uploader") is NOT implemented yet — `pf ingest` requires an explicit `--discipline` flag. Why: auto-classification is explicitly S2's job (Phase 3), which hasn't started; the spec itself allows uploader override, so requiring it explicitly for now is within spec, not a shortcut around it. Revisit once Phase 3 lands — `--discipline` should become optional, auto-detected, and still overridable.

## Known Issues
- `ingest/metadata.py`'s title-page regex heuristic only handles the `Title:`/`Author:`/`Edition:` literal-field format used by the synthetic test fixtures (`scripts/make_fixtures.py`). It will not reliably extract metadata from a real scanned textbook's title page (publisher boilerplate, ISBN blocks, no literal "Title:" label). Tracked in `docs/adr/0004` — needs an LLM pass before it's usable on real books; not blocking Phase 2's gate, which only needs metadata good enough to prove the *matching* logic works.
- `ingest/extract.py`'s `has_math` detection is a regex hint (`=`, `∫`, `\frac`, etc.), not real math-region parsing, and `has_figure` only checks whether pypdf reports embedded raster images — vector-drawn figures (most textbook diagrams) won't be detected. Both are placeholders for marker-pdf's real output; not exercised by anything downstream yet since Phase 4 (Figures) hasn't started.
- `mypy --strict` / `ruff` now run clean against all of `src/practice_forge/` (verified this session, not just asserted): fixed a real `ruff`-caught blind-except without justification, an inline-able conditional, unsorted imports, JSONB columns missing generic `dict[str, Any]` type args, and added `[[tool.mypy.overrides]]` for `docker`/`datasketch` (neither ships a `py.typed` marker; `docker` specifically needed `follow_imports = "skip"`, not just `ignore_missing_imports`, because mypy was walking its untyped source and tripping on a dynamic re-export rather than just failing to find it). `scripts/` (fixture-generation only, not platform or student-facing code) is excluded from both tools' scope in `pyproject.toml`.
- No real marker-pdf integration yet (see `docs/adr/0004`) — everything ingested so far is synthetic, genuinely-text-based fixture PDFs, not a real scanned/printed textbook. First real textbook PDF will be the actual test of whether `pypdf`'s extraction is good enough to carry the pipeline forward, or whether marker-pdf needs to be pulled in sooner than planned.
- Host venv (`.venv/`, gitignored) is Python 3.11, not the spec's 3.12 — sandbox/worker/api containers are unaffected (true `python:3.12-slim`). Unchanged from Phase 1.
