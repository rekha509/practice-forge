## Decisions Made
(Phase 1/2/3-original decisions unchanged — see prior history / `docs/adr/0001-0005`.)
- Provider-agnostic `Backend` protocol + YAML-driven per-stage routing, instead of a single hardcoded Anthropic client. Why: the Anthropic-billing dead end plus Gemini's completely different constraint shape (RPD, not cost) made it obvious this would need to change again — better to make "which provider serves which stage" a config edit than a code change, permanently, not just for this one pivot.
- Rate limiting is enforced in-process (token bucket + a persisted JSON daily counter), not left to the provider SDK's own retry behavior. Why: Gemini's constraint is a hard daily wall, not a transient backoff-and-retry situation — retrying into an exhausted RPD quota just wastes time and risks the SDK's own retry loop masking a real stop condition. `DailyQuotaExhausted` is raised, not retried, by design.
- Every high-volume stage batches N items into one call (`llm/batching.py`), keyed by an explicit `index` field for alignment rather than trusting response order. Why: ~250-1000 requests/day cannot cover per-item calls for any real textbook; and trusting positional alignment would silently mismatch results the moment a model drops or reorders one element.
- `thinking_budget=0` is NOT set for `gemini-flash-lite-latest` stages (s2/s3/s6) even though the model doesn't think by default — found live that passing `thinking_budget=0` explicitly is a 400 for this model, while omitting the field entirely produces the identical "no thinking" behavior. Documented in `config/llm_routing.yaml` inline, not just in the ADR, so it doesn't get "helpfully" re-added later.
- S8/S9 (variant generation, code generation) route to `gemini-flash-latest`, not a Pro-tier model — because no Pro-tier model has any free-tier quota on this account at all (confirmed via live 429s quoting `limit: 0` on every quota dimension). This was an explicit user decision after being presented with the tradeoff, not a silent downgrade.
- PEP 695 generic function syntax (`def f[T](...)`) was tried in `llm/batching.py`, caught by mypy as a parse error, and reverted to classic `TypeVar` — this host's dev venv is Python 3.11 (no 3.12 interpreter available, unchanged fact from Phase 1), and that syntax doesn't even parse there, regardless of what `pyproject.toml`'s `requires-python`/ruff's `target-version` claim. `# noqa: UP047` marks the deliberate downgrade.
